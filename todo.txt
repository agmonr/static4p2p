Project: Decentralized P2P Chat + Voice Static Web App
Goal

Create a static webpage (deployable on GitHub Pages or any static hosting) that enables:

1-to-1 encrypted chat
voice communication
optional group communication
no backend owned by the application
P2P-first architecture
decentralized discovery/fallback

6. Peer Discovery Module

Create an abstraction:

DiscoveryProvider
{
 publishPeer()

 findPeer()

 updateAddress()
}

Primary implementation: BitTorrent tracker signaling

Use WebTorrent-style WSS trackers (e.g. tracker.openwebtorrent.com,
tracker.btorrent.xyz) as the rendezvous/signaling channel.

Note: this is NOT the mainline Kademlia DHT. Browsers cannot open raw
UDP sockets, so real BitTorrent DHT is out of reach client-side.
WSS trackers are the browser-reachable equivalent — a public backend,
just not one the app owns or hosts.

Infohash = rendezvous point:

infohash = hash(pubkeyA + pubkeyB + sharedSalt)

Derive from a shared secret established during pairing (section 3),
never from public info alone (e.g. not just hash(pubkey)). Otherwise
anyone watching public trackers can enumerate who is talking to whom
by observing swarm joins, even without reading message content.

Groups (section 9): one infohash per group = one swarm. Swarm
join/leave already models multi-peer membership, so group topology
can build on this instead of a bespoke membership protocol.

Limitations:
- Rendezvous only. Does not solve NAT traversal (see section 4).
- Peer must be actively announcing to be found — does not solve
  offline delivery (see section 7).
